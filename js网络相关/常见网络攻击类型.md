# XSS跨站脚本攻击
XSS攻击者通过在网页中注入恶意脚本，并使这些脚本在浏览器中运行，从而达到窃取用户信息的目的

XSS攻击的方式可分为三类，分别是：存储型、反射型以及DOM型

**存储型XSS攻击：**
黑客通过将脚本写入评论区等输入框中从而将脚本注入服务器的数据库中，于是，当其他用户访问该评论区时，数据库中的脚本也会被返回执行，从而触发XSS攻击
```js
<script>alert('你被攻击了！')</script>

```
**反射型XSS攻击：**
在反射型XSS攻击中，恶意脚本被以参数的形式写在URL中，黑客通过这种方法向目标用户发送带有脚本的恶意链接，从而触发脚本
```js
https://example.com/search?q=<script>stealCookies()</script>

```
**DOM型XSS攻击**
区别于反射型XSS攻击将恶意脚本写在URL中，DOM型XSS攻击则是利用客户端原有的js脚本来实现，最常见的一种就是利用锚点来嵌入脚本

锚点的存在一般是为了方便用户跳转并减少URL请求，但通过将恶意脚本写进锚点，从而伪造链接，就会导致基于原有DOM操作的恶意脚本触发
```js
document.getElementById("output").innerHTML = location.hash;

```

# CSRF跨站请求伪造攻击
我们都知道，http是一种无状态协议，也就是说，http并不会记录用户信息，这就导致了用户每次登录时都要进行身份验证，为解决这个问题，浏览器的策略是使用cookie来记录用户的身份信息，当用户向服务器发送请求时，只要携带了cookie，服务器就默认为用户的请求“放行”

CSRF跨站请求攻击正是利用了浏览器的cookie策略，当黑客获取了用户的cookie后，他们可以写一个“伪造”的网页，再诱导目标点击链接进入该网页，如果用户用相同的浏览器打开，那么其中的脚本就能向服务器发送伪造的请求，由于携带cookie，请求被识别成功，恶意脚本就能发挥作用，造成用户财产或账户的损失

**应对策略：**
1. CSRF Token：用户登录后，服务器同时生成一个随机的、不可预测的token，并返回存入用户本地或数据库中，再后续请求中需要携带该token以验证用户身份，由于随机生成的token无法预测，所以能有效防止CSRF攻击
2. SameSite属性：通过设置SameSite=Strict来确保只有本站域名携带cookie才能被接收，从而防止CSRF的跨站伪造攻击
3. 设置CORS跨域：开启CORS的信任域名，从而防止未知域名的请求
# DDOS攻击（Distributed Denial of Service）
DDOS攻击是一种针对网站服务的攻击，攻击者通过在短时间内发送大量请求，导致服务器瘫痪，从而无法向正常用户提供服务
